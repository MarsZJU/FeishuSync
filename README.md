# FeishuSync · 飞书备份
一个轻量的 macOS 菜单栏工具，将飞书云文档自动备份到本地文件夹或 iCloud Drive。


## 用途 
AI 时代，每个人都可以建立自己的数字化资产，将自己数字化，更充分的与AI结合。用飞书云文档编辑自己的文稿，再通过这款应用导出为 Markdown 或 PDF 文件并同步到本地，使用Codex/Claude Code 或其他 Agent 应用阅读这些文档，充分利用AI。

**在飞书里编辑，在自己的电脑上保留一份。**
## 功能

- **菜单栏操作**：同步、暂停、打开备份目录和设置。
- **多个备份位置**：每个文件夹可以配置不同的文档。
- **自动选择格式**：纯文本导出 Markdown，含图片导出 PDF。
- **手动指定格式**：支持固定 Markdown 或 PDF。
- **定时同步**：可选每 5 分钟或 30 分钟。
- **清爽的输出目录**：每篇文档直接保存为一个文件，沿用远端标题。
- **失败保护**：导出验证成功后才更新文件，失败时保留原备份。

这是单向备份工具，本地修改不会回写飞书。

## 环境要求

- Apple Silicon Mac
- macOS 13 或更高版本
- 已安装并配置官方 [Lark CLI](https://github.com/larksuite/cli)
- 当前登录用户具有对应文档的读取和导出权限

当前构建目标为 Apple Silicon，尚未提供 Intel 版本和 Windows 版本。

## 开始使用

### 1. 配置飞书 CLI

先安装 Node.js（包含 npm/npx），然后在终端运行官方安装命令：

```sh
npx @larksuite/cli@latest install
```

安装后，按照 [Lark CLI 官方说明](https://github.com/larksuite/cli)完成应用配置和用户授权。

已配置过 CLI 的用户可以直接复用现有登录。需要登录时运行：

```sh
lark-cli auth login
```

### 2. 打开应用

解压应用安装包，双击 `FeishuSync.app`。也可以按照下文从源码构建。

启动后，屏幕顶部菜单栏会显示云朵循环箭头图标。点击图标，选择“设置与同步详情”。

应用默认使用 `/opt/homebrew/bin/lark-cli`；如果你的安装位置不同，可以在设置的“CLI 与登录”中修改。

### 3. 添加备份内容

首次使用没有预置的文档或备份位置。

1. 点击“添加备份位置”，选择本地文件夹或 iCloud Drive 文件夹。
2. 点击备份位置，展开文档列表。
3. 点击“添加文档”，粘贴飞书文档链接。
4. 选择导出格式，点击“同步”。

需要定时备份时，启用自动同步并选择间隔。

## 导出格式

| 选项 | 行为 |
| --- | --- |
| 自动 | 纯文本导出 Markdown，含图片导出 PDF |
| 固定 Markdown | 始终导出 Markdown，适用于新版飞书文档 |
| 固定 PDF | 始终导出 PDF |

自动模式遇到画板、公式、嵌入内容或无法确认的非文字结构时，也会选择 PDF。旧版文档和幻灯片使用 PDF。

复杂内容的最终呈现取决于飞书的导出能力。

## 文件保存方式

所选文件夹中直接保存文档，例如：

```text
我的备份/
├── 学习笔记.md
└── 项目资料.pdf
```

同一文档再次同步时更新对应文件。不同文档重名或遇到已有用户文件时，应用会使用带标识后缀的文件名，避免覆盖。

配置、同步记录和历史版本保存在：

```text
~/Library/Application Support/FeishuSync/
```

移除同步条目不会删除已导出的文件。历史版本不会自动清理，会逐渐占用本机空间。

## 使用边界

- 只同步明确添加的文档，不递归同步 Wiki 子页面。
- 支持文档、对应 Wiki 页面及幻灯片；不支持电子表格和多维表格。
- 自动同步需要应用运行，且 Mac 清醒、联网。
- 关闭设置窗口后应用继续驻留菜单栏；退出应用后停止同步。
- 不会保持电脑常醒，也不保证合盖时同步。
- iCloud 跨设备同步由 macOS 负责。
- 本项目是独立工具，并非飞书官方客户端。

## 从源码构建

安装 Xcode Command Line Tools 后，在项目目录执行：

```sh
bash build.sh
```

构建产物：

```text
build/FeishuSync.app
build/FeishuSync.zip
```

运行测试：

```sh
bash test.sh
```

测试使用虚构文档与模拟响应，不访问真实飞书账号，不需要登录。

应用使用 Swift、SwiftUI 和 AppKit 开发，文档访问和导出通过官方 Lark CLI 完成。

当前构建采用本机临时签名，尚未进行 Apple 开发者签名和公证。

## 常见问题

### 登录失效怎么办？

在终端运行：

```sh
lark-cli auth login
```

完成授权后回到应用重新同步。同步正常时无需重复登录。

### 为什么含图片的文档导出为 PDF？

PDF 更适合保存图片和页面布局。需要 Markdown 时可以手动切换，但图形内容可能丢失。

### 同步失败会损坏已有文件吗？

应用先在临时目录中导出并检查结果，成功后才更新目标文件。导出失败时保留已有备份。
